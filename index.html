Overview

Executive
Summary

This report presents the findings of a WCAG 2.1 accessibility audit conducted on the Amex GBT Egencia corporate travel booking platform. The audit covered 7 key screens across the core user journey — from the public landing page through to booking confirmation.

A total of 21 accessibility findings were identified, including 8 Critical violations, 7 Major issues, and 6 Minor concerns. Notably, the majority of critical failures are Level A violations — the most fundamental tier of accessibility compliance — meaning the platform does not meet baseline accessibility requirements as defined by WCAG 2.1.

These issues have real consequences. Corporate travelers who rely on screen readers, keyboard navigation, or assistive technologies may be unable to complete a booking independently — a significant usability gap and potential legal compliance risk under the ADA, EN 301 549, and the Equality Act.

Key failures include: both form fields on the login page lack programmatic labels; a critical travel disruption alert has no ARIA live region; icon-only amenity indicators convey essential booking information without any text alternative; and no visible focus indicator exists for keyboard navigation across any audited screen.

Automated Scanning

axe DevTools (v4.11.1) and WAVE (WebAIM) were used to identify programmatic accessibility violations on all publicly accessible pages. Automated tools reliably surface issues such as missing labels, invalid ARIA usage, and structural problems.

Detailed Findings

All 21 Findings

Login Page
F-01 Missing Form Labels Login Critical
WCAG1.3.1 / 4.1.2
LevelA
ToolWAVE — 2 errors

Both the "Username or email" and "Password" input fields lack programmatic labels. Placeholder text is being used as a substitute — when a user begins typing, the placeholder disappears, leaving screen reader users with no context about what the field requires.

This effectively blocks independent login for users relying on screen readers (NVDA, JAWS, VoiceOver) and voice control tools.

Recommendation

Add explicit <label> elements associated with each input via matching for and id attributes.

/* Current — inaccessible */ <input type="text" placeholder="Username or email" /> /* Recommended */ <label for="username">Username or email</label> <input type="text" id="username" name="username" />
F-02 Missing Page Language Declaration Login Critical
WCAG3.1.1
LevelA
ToolWAVE + axe

The HTML document does not declare a language via the lang attribute. Screen readers use this to determine which language engine and pronunciation rules to apply. Without it, text-to-speech tools may default to an incorrect language.

Recommendation
<html lang="en">
F-08 Missing Visible Focus Indicator Login Critical
WCAG2.4.7
LevelAA
ToolManual keyboard test

When navigating using only a keyboard (Tab key), there is no visible focus indicator showing which element is currently active. The browser's default focus outline appears to have been suppressed via CSS with no custom replacement provided.

This affects all keyboard-only users, including users with motor disabilities, power users, and users with cognitive disabilities who rely on clear visual cues.

Recommendation
:focus-visible { outline: 2px solid #2563FF; outline-offset: 2px; border-radius: 4px; }
F-03 Orphaned Form Labels Login Major
WCAG1.3.1
LevelA
ToolWAVE — 2 alerts

Two <label> elements exist in the markup but are not correctly associated with any input field. They are orphaned — serving no functional purpose for assistive technologies.

Recommendation

Ensure each <label> has a for attribute matching the id of its corresponding input.

F-04 Missing Main Landmark Login Major
WCAG1.3.6
LevelAAA (Best Practice)
Toolaxe

The page contains no <main> landmark. Screen reader users who navigate by landmarks cannot jump directly to the login form, and must tab through all navigation elements first.

Recommendation

Wrap the login form content in a <main> element. Ensure all page content sits within appropriate landmark regions.

F-06 Tabindex Greater Than Zero Login Major
WCAG2.4.3
LevelA
Toolaxe

An element has a tabindex value greater than 0, overriding the browser's natural tab order and creating an unpredictable, disorienting keyboard navigation experience.

Recommendation

Remove all positive tabindex values. Use tabindex="0" for natural tab order inclusion only.

F-05 Missing Level-One Heading Login Minor
WCAG1.3.1
LevelA
Toolaxe

"Log in to your Egencia account" serves as the page title visually but is not marked as <h1>, breaking the document outline that screen reader users rely on.

F-07 Content Outside Landmark Regions Login Minor
WCAG1.3.6
LevelAAA (Best Practice)
Toolaxe — 7 elements

Seven content elements sit outside any landmark region. Screen reader users navigating by landmarks will skip this content entirely.

Landing Page
F-09 Invalid Heading Order Landing Page Minor
WCAG1.3.1
LevelA
Toolaxe — moderate

Heading levels skip non-sequentially — jumping from <h1> to <h3> without an intervening <h2>. This breaks the logical document outline screen reader users rely on.

Recommendation

Ensure heading levels follow a sequential hierarchy. Use CSS for visual sizing, not heading level changes.

Dashboard
F-10 Icon-only Navigation Without Accessible Labels Dashboard Critical
WCAG1.1.1 / 4.1.2
LevelA
ToolManual

The primary navigation (Flights, Hotels, Trains, Cars) uses icons that may lack proper ARIA attributes. If icons are not marked as decorative with aria-hidden="true", screen readers may announce file names or redundant descriptions alongside visible labels.

Recommendation

Mark decorative navigation icons with aria-hidden="true" so screen readers rely solely on the visible text labels. For icon-only contexts, add aria-label to the parent element.

F-11 Critical Alert Banner Missing ARIA Live Region Dashboard Critical
WCAG4.1.3
LevelAA
ToolManual

The "Middle East Update — Disruption" banner communicates a safety-critical travel alert but lacks role="alert" or aria-live. Screen reader users will not be automatically notified of this banner — they could miss a safety-critical disruption notice entirely.

Recommendation
<div role="alert" aria-live="assertive"> Middle East Update — Disruption... </div>
Flight Search Results
F-12 Amenity Icons Without Text Alternatives Search Results Critical
WCAG1.1.1
LevelA
ToolManual

Each flight card displays icons representing included amenities (seat type, baggage, meal, wifi). These icons convey information that directly influences booking decisions but appear to have no text alternative, tooltip, or aria-label. Screen reader users receive no amenity information.

Recommendation

Add descriptive aria-label to each icon. This is a systemic fix required at the design system level — the icon component should require an accessibleLabel prop.

F-13 Color as Only Means to Convey Policy Status Search Results Major
WCAG1.4.1
LevelA
ToolManual

A red flag icon indicates out-of-policy fares using color as the primary signal. Users with red-green color blindness (approximately 8% of males) may not perceive this distinction.

Recommendation

Add a visible text label "Out of policy" alongside the flag icon. Add aria-label="Out of policy" to the flag element.

F-14 Filter Bar Overflow Without Scroll Affordance Search Results Minor
WCAG1.3.1
LevelA
ToolManual

The filter bar overflows its container with "Sustainability" truncated at the right edge. No visible scroll affordance or indicator informs users that additional filters exist beyond the visible area.

Customize Flight
F-15 Decorative Image Missing Null Alt Attribute Customize Flight Minor
WCAG1.1.1
LevelA
ToolManual

A purely decorative flight summary image likely lacks alt="". Screen readers will read out the file name, creating unnecessary noise during a complex multi-step form.

Recommendation
<img src="flight-hero.jpg" alt="" role="presentation" />
F-16 Seat Unavailability Message Lacks Actionable Context Customize Flight Minor
WCAG1.3.3
LevelA
ToolManual

"Seat selection will be available at check in" provides no context about when check-in occurs or what action to take. Users with cognitive disabilities may not understand their next step.

Recommendation

Add persistent context: "You'll be able to choose your seat during online check-in, which opens 24 hours before departure."

Traveler Information Form
F-17 Mandatory Fields Indicated by Color and Symbol Only Traveler Form Major
WCAG1.4.1 / 1.3.1
LevelA
ToolManual

Required fields use a red asterisk (*) as the sole indicator of mandatory status — not communicated programmatically. Screen reader users may submit incomplete forms without prior warning of required fields.

Recommendation
<input type="text" aria-required="true" required />
F-18 Date Fields Use Disappearing Placeholder as Format Guide Traveler Form Major
WCAG3.3.2
LevelA
ToolManual

Date fields use mm/dd/yyyy as placeholder text — which disappears on focus. This is especially problematic for users on egencia.co.in (India) where dd/mm/yyyy is the standard format.

Recommendation

Replace placeholder format hints with persistent helper text below the field. Ideally use a date picker component to eliminate format ambiguity entirely.

F-19 Phone Fields Default to Incorrect Country Code Traveler Form Minor
WCAG1.3.4
LevelAA
ToolManual

All three phone fields default to US (+1) country code despite the platform being accessed via the Indian domain (egencia.co.in). Creates friction for international users during a time-sensitive booking flow.

Recommendation

Auto-detect locale from browser settings or user profile to pre-populate the correct country code.

Booking Confirmation
F-20 Draft Status Banner Not Announced to Screen Readers Confirmation Major
WCAG4.1.3
LevelAA
ToolManual

"Saved as a draft — This reservation is not yet booked" is a critical status message. Without role="status" or aria-live, screen reader users may believe their booking is confirmed when it is not — a high-stakes misunderstanding.

Recommendation
<div role="alert" aria-live="assertive"> Saved as a draft. This reservation is not yet booked. </div>
F-21 Amenity Icons Repeated Without Labels (Systemic) Confirmation Critical
WCAG1.1.1
LevelA
ToolManual

The inaccessible amenity icons from F-12 reappear in the itinerary detail without text alternatives. This is a systemic design system issue — the icon component does not support accessible labels by default.

Recommendation

Update the icon component library to require an accessibleLabel prop as mandatory. Conduct a product-wide icon audit to identify all other instances.

"The most critical failures here aren't edge cases — they're overlooked fundamentals."

This audit reinforced how many accessibility failures stem from decisions made early in a product's life — placeholder labels, suppressed focus styles, icon-only components — that compound over time into significant barriers for users who depend on assistive technologies.

The good news: the majority of critical issues identified here are well-understood problems with well-understood solutions. Many require minimal development effort but deliver outsized impact. Embedding accessibility into the design process from the start — through accessible component libraries, regular automated scanning, and inclusive user research — is the most effective long-term strategy at Egencia's scale.
